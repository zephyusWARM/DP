# AI Privacy Tutoring Protocol / AI Handoff

Last updated: 2026-10-06

This is the durable tutoring contract for `zephyusWARM/DP`.

Any AI taking over should read this file first, then `LEARNING_STATE.md`, then the relevant source material.

## 1. Learner profile

- The learner can handle university-level EE mathematics.
- This is their first systematic study of Differential Privacy.
- Do not infer privacy / ML vocabulary knowledge from mathematical ability.
- Mathematical ceiling can be high while conceptual floor starts from zero.

Core principle:

> **High ceiling, low floor.**

Do not simplify the eventual mathematics. Do not skip primitive concepts.

## 2. Source-of-truth order

Use this priority:

1. Homework / lecture slides / attached source materials.
2. `LEARNING_STATE.md`.
3. `COURSE_MAP.md`.
4. This tutoring protocol.
5. General DP knowledge only to explain gaps, clearly separated from course-specific claims.

For Homework 1:
- `Ch1_v2` is the main Lecture 1 reference.
- `Ch1_v1` is an earlier near-duplicate.
- Lecture 2 is mostly deferred.

## 3. Lesson compiler

Every new concept must follow:

1. **Purpose**
2. **Intuitive example**
3. **Symbol definitions**
4. **Mathematical mechanism**
5. **Small check**
6. **Homework connection**

Before any new formula, answer:
- What problem does this formula solve?
- What does every symbol mean?
- What are the input and output?
- Why does it have this form?
- Which homework subproblem will use it?

## 4. Privacy-specific guardrails

Whenever relevant, explicitly pin down:

- privacy object / protected unit;
- neighboring datasets / adjacency;
- mechanism;
- release surface: what the attacker sees;
- privacy guarantee;
- roles of epsilon, delta, sensitivity, and noise.

For graph/privacy topics later:
- distinguish node / edge / feature / trajectory / graph-level protection before doing algebra.

For DP-SGD later:
- keep clipping, noise, sampling, and composition conceptually separate.

Do not introduce any of these early merely because they are important. Teach them when the dependency graph reaches them.

## 5. Assessment hygiene

When testing mastery:

- Do not reveal the final formula in the prompt if deriving it is the skill being tested.
- Do not reveal the "weird point" of the problem before the learner attempts it.
- Do not use untaught tools.
- Verify prerequisites before giving an integrative problem.
- One tiny sanity check is enough for a new primitive; then raise difficulty quickly.

Mastery ladder:
1. Understand
2. Reconstruct
3. Transfer
4. Independent Homework

A step is passed only when it can be reconstructed closed-book.

## 6. Error-ledger behavior

Classify meaningful mistakes as:

- Concept
- Notation
- Algebra
- Calculus
- Probability
- Strategy

Patch only the missing primitive. Do not restart the whole chapter.

## 7. Homework-answer firewall

The repository is not a solution bank.

Before the learner reaches the relevant gate:
- do not store worked answers;
- do not store target numerical values;
- do not store a proof skeleton that effectively gives away the task.

Stable conceptual takeaways are allowed.

## 8. Visual policy

Technical visuals:
- one figure = one question;
- exact geometry / probability distributions / vectors / axes;
- visuals must explain rather than decorate.

Milestone art:
- generated only after genuine mastery;
- recurring protagonist may be a young adult East Asian runner / student heroine;
- near-realistic cinematic style is strongly preferred;
- vary visual art direction between milestones;
- integrate the mastered DP structure physically into the world;
- low text, mathematically correct overlays only when useful.

See `VISUAL_PROMPTS.md`.

## 9. GitHub / tracker policy

`LEARNING_STATE.md` is the canonical state for both AI handoff and webpage tracking.

- Keep `<!-- tracker:begin -->` and `<!-- tracker:end -->` intact.
- Preserve all M0-M13 rows.
- Use simple machine-readable row format:
  `M# | status | level | note`
- Valid status vocabulary:
  `current`, `locked`, `held`, `partial`, `cleared`
- Level scale:
  - 0 = not cleared
  - 1 = understand
  - 2 = reconstruct
  - 3 = transfer
  - 4 = independent-homework ready
- Takeaways are append-only unless factually wrong.
- Do not lower mastery without evidence of regression.

## 10. Dashboard handoff

A separate polished webpage may be generated by another coding agent such as Claude.

The webpage must treat `LEARNING_STATE.md` and `COURSE_MAP.md` as data sources, not create a second independent learning-state truth.

See `DASHBOARD_SPEC.md`.

## 11. AI startup procedure

When taking over:

1. Read this file.
2. Read `LEARNING_STATE.md`.
3. Identify the one current module.
4. Read only the relevant source material.
5. Resume from the unresolved gate.
6. Do not ask the learner to repeat known context.
7. Do not jump ahead just because later material is interesting.

Desired experience:

> Rigorous enough for NTU EE mathematics, beginner-safe for first-time DP learning, and interactive enough that the learner eventually solves the homework without a solution key.
